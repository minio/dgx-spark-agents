Name mapping in 10 bullets (read the cited line first):

1. Purpose: bridge Iceberg's id-based column identity to the name-based schemas of files that carry no field ids (e.g. imported Hive/Parquet data). Spec: format/spec.md:412 ("schema.name-mapping.default" property).

2. Data model: a JSON list of objects, each with `names`, optional `field-id`, optional nested `fields`. In code that's `MappedField` (core .../mapping/MappedField.java:46-54) with `names` set, nullable `id`, nullable `nestedMapping`.

3. The nested tree: `NameMapping` wraps a top-level `MappedFields`, whose `fields()` list of `MappedField`s mirrors the JSON. core .../mapping/NameMapping.java:49-57 and MappedFields.java:39.

4. Dotted-lookup: nested names are joined with a literal `.`; `find(List<String>)` resolves a full path. core .../mapping/NameMapping.java:63-77 and MappingUtil.java:196-213 (IndexByName).

5. Reserved child names: lists must map `element`; maps must map `key` and `value`. Generated by MappingUtil.java:296-305 (CreateMapping); looked up in ApplyNameMapping.java:98 and :122-123.

6. Serialization: custom JSON codec, kebab-case keys (`field-id`, `names`, `fields`), optional fields written only when present. core .../mapping/NameMappingParser.java:47-49 and :69-83.

7. Uniqueness guard: duplicate field ids throw when the by-id index is built. core .../mapping/MappingUtil.java:233-239 (Preconditions.checkState).

8. Where it's applied at read time: the format reader's `getId`/`getFieldId` fall back to the name mapping only when the file lacks the id property. core .../avro/AvroSchemaUtil.java:307-315 and :411-419; ApplyNameMapping.java:54-59.

9. Maintenance: kept in lockstep with schema evolution (renames/adds) via MappingUtil.update, best-effort (warns, never fails the commit). core .../SchemaUpdate.java:484-505.

10. How engines use it: read the table property, parse it, hand to the reader builder. Spark: spark/v4.1/.../source/BaseReader.java:100-102 then BaseBatchReader.java:94; Flink: flink/v1.20/.../source/RowDataFileScanTaskReader.java:111-113.

Rule of thumb: the mapping only matters for files without ids — ids in the file always win; everything else is plumbing that carries the parsed `NameMapping` from table properties down to the format reader.
